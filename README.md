# Task-1

· a = 42: В двоичном виде это 00000000 00000000 00000000 00101010. · b = -17:
Модуль числа: 17 = 10001_2.
Прямой код (32 бита): 00000000 00000000 00000000 00010001.
Обратный код (инвертируем биты): 11111111 11111111 11111111 11101110.
Дополнительный код (прибавляем 1): 11111111 11111111 11111111 11101111.
Результаты операций:
· a & b (Побитовое И): 000...00101010 111...11101111
000...00101010 (совпадают только биты, где у a единицы, а у b в этих позициях тоже единицы. В данном случае это биты 1, 3, 5). Результат: 42. · a | b (Побитовое ИЛИ): 000...00101010 111...11101111
111...11101111 (Везде, где есть хотя бы одна единица, ставим 1. Так как b почти весь состоит из единиц, результат будет равен b). Результат: -17. · a ^ b (Побитовое исключающее ИЛИ): 000...00101010 111...11101111
111...11100101 (Единица там, где биты разные. Инвертируем те биты b, где у a стоят единицы). Результат: -59. (Проверка: -17 ^ 42). · ~a (Побитовое НЕ): Инвертируем все биты числа 42 (000...00101010 -> 111...11010101). Результат: -43. (Формула: ~x = -x - 1). · a << 2 (Сдвиг влево): Сдвигаем биты влево на 2 позиции, справа добавляются нули. Это эквивалентно умножению на 2^2 = 4. 42 * 4 = 168. Результат: 168. · a >> 2 (Сдвиг вправо): Сдвигаем биты вправо на 2 позиции. Для положительных чисел слева добавляются нули. Эквивалентно делению на 2^2 = 4 с отбрасыванием остатка. 42 / 4 = 10 (остаток 2). Результат: 10. · b << 2 (Сдвиг влево): Сдвигаем -17 влево на 2. Эквивалентно умножению на 4. -17 * 4 = -68. Результат: -68. · b >> 2 (Сдвиг вправо): Для отрицательных чисел используется арифметический сдвиг: слева добавляются единицы (знаковый бит сохраняется). Это эквивалентно делению на 4 с округлением вниз (в сторону минус бесконечности). -17 / 4 = -4.25. Округляем вниз до -5. Результат: -5.

Число -1 в 32-битной системе:
· Прямой код: 10000000 00000000 00000000 00000001 (старший бит — знак минуса). · Обратный код: 11111111 11111111 11111111 11111110 (инвертируем все биты, кроме знакового). · Дополнительный код: 11111111 11111111 11111111 11111111 (к обратному коду прибавляем 1).

ДОПОЛНИТЕЛЬНЫЙ КОД
Устройство: Дополнительный код положительного числа совпадает с прямым. Для отрицательного числа: берется модуль числа, инвертируются все биты (получается обратный код), и к результату прибавляется единица.
Причина появления:
Устранение проблемы "двух нулей": В прямом и обратном коде существуют +0 и -0, что неудобно для процессора. В дополнительном коде ноль единственный (000...000).
Упрощение аппаратуры: Дополнительный код позволяет заменить операцию вычитания операцией сложения. Процессору не нужен отдельный блок для вычитания, достаточно иметь сумматор. Например, a - b превращается в a + (~b + 1).
Расширение диапазона: В дополнительном коде можно представить на одно отрицательное число больше, чем положительных (например, для 8 бит: от -128 до 127).
Почему при сдвиге вправо отрицательных чисел результат остаётся отрицательным?
При сдвиге вправо отрицательного числа используется арифметический сдвиг. В отличие от логического сдвига (где освободившиеся слева биты заполняются нулями), при арифметическом сдвиге освободившиеся биты заполняются значением знакового бита (крайнего левого бита).
Так как у отрицательных чисел знаковый бит равен 1, при сдвиге вправо слева подставляются единицы. Это сохраняет знак числа и эквивалентно делению на степень двойки с округлением вниз (например, -5 >> 1 даст -3, а не -2). Если бы заполняли нулями, число стало бы положительным, что нарушило бы арифметику.
